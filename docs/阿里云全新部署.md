# 全新阿里云部署 Hydro（官方方式）

依据 [hydro-dev/Hydro](https://github.com/hydro-dev/Hydro) 与 [官方安装文档](https://hydro.js.org/zh/docs/Hydro/install)。

**不要**在服务器上 `git clone https://github.com/hydro-dev/Hydro` 再自己编译。生产安装走官方脚本，用 Nix 装好 Node / MongoDB / Caddy / 评测沙箱，由 PM2 托管。FishOJ 只是事后挂上的插件。

旧机数据迁过来见 [`换机迁移.md`](换机迁移.md)。本文只覆盖：**空机器 → 能打开 Hydro 官网式空白站**。

---

## 1. 买机时注意（官方硬性要求）

| 项 | 选什么 | 不要选 |
|----|--------|--------|
| 系统 | **Ubuntu 22.04** 或 **Debian 12**（x86_64） | Alibaba Cloud Linux、CentOS、TencentOS、OpenCloudOS（官方明确不支持） |
| 规格 | 建议 ≥ 4C8G（评测 + 插件）；官方最低 1C2G | 突发性能 / 共享型（计时不准） |
| 面板 | 纯净系统 | 宝塔 / 1Panel（官方不支持、有安全风险） |
| Docker | 本阶段不用 | 官方对 Docker 不提供免费支持；容器还需 `--privileged` |

内存 ≤2G 时官方更推荐 Debian 12，Ubuntu 22.04 更吃内存。FishOJ 现网是 Ubuntu 22.04 4C8G。

---

## 2. 阿里云安全组

脚本会在**本机**占用这些端口（保持空闲即可）：`80, 443, 2019, 8888, 5050, 27017`。

安全组**只对公网放行**：

- `22` SSH
- `80` HTTP（有域名备案后再加 `443`）

**不要**把 `27017`（Mongo）、`8888`（Hydro 内网）、`5050`（沙箱）暴露到 `0.0.0.0/0`。

控制台路径：ECS → 实例 → 安全组 → 入方向。装完打不开网站，多半是没放行 80，不是 Hydro 没装上。

## 3. 一键安装（官方命令）

SSH 登录后立刻切 root（安装与之后所有 `hydrooj` / `pm2` 都必须是 root）：

```bash
sudo su
# 确认
whoami          # 必须是 root
cat /etc/os-release
```

官方安装（清华镜像，国内云常用）：

```bash
LANG=zh . <(curl https://hydro.ac/setup.sh)
```

可选参数（一般**不要**加）：

- `--no-caddy`：不装 80 反代，只听 `127.0.0.1:8888`（已有 Nginx 才用）
- `--judge`：只装评测机

Nix 镜像失败时可换源再跑：

```bash
nix_install_source=https://mirrors.ustc.edu.cn/nix/latest/install LANG=zh . <(curl https://hydro.ac/setup.sh)
```

等到提示安装成功。新开一个 root 登录（加载 nix/pm2）：

```bash
bash -lc 'pm2 list'
```

应看到类似：`hydrooj`、`mongodb`、`hydro-sandbox`、`caddy`，状态 online。

浏览器打开：`http://<新机公网IP>/`  
能出 Hydro 注册页即核心部署成功。

## 4. 第一个管理员

README 写「首个注册用户自动超管」；安装文档仍建议手动指定。稳妥做法：

1. 网页注册第一个账号。
2. 服务器执行（uid 一般是 `2`，以控制面板用户列表为准）：

```bash
hydrooj cli user setSuperAdmin 2
```

刷新后应出现「控制面板」。系统设置里 **Server BaseURL** 填完整地址且以 `/` 结尾，例如：

```
http://x.x.x.x/
```

有域名后再改成 `https://你的域名/`。

## 5. 装完东西在哪（FAQ）

| 内容 | 路径 |
|------|------|
| 配置、插件 | `/root/.hydro/`（另有 `/root/.config/hydro`） |
| Mongo 数据文件 | `/data/db`（不要直接拷目录，用 backup） |
| 题目文件 / 测例 | `/data/file` |
| 静态资源 | `/root/.hydro/static` |
| 官方备份 | `hydrooj backup` → 当前目录 zip；`hydrooj restore 文件.zip` |

更新 Hydro **不要改 Nix 里的官方包**，用插件扩展（FishOJ 的 `addons/`）。

## 6. 再挂 FishOJ 插件（空白站能开之后）

从本仓库拷插件到新机，再注册：

```bash
# 本机
scp -r addons/ProblemIde addons/LearningScaffold addons/AiTutor \
  addons/AiAssistant addons/AiAnalysis addons/OfficialSolution \
  addons/HomePage addons/VipIntroPage addons/FishOjTheme addons/hydroac-client \
  root@<新IP>:/root/.hydro/addons/

ssh root@<新IP> "bash -lc '
  hydrooj addon add /root/.hydro/addons/ProblemIde
  hydrooj addon add /root/.hydro/addons/LearningScaffold
  hydrooj addon add /root/.hydro/addons/AiTutor
  hydrooj addon add /root/.hydro/addons/AiAssistant
  hydrooj addon add /root/.hydro/addons/AiAnalysis
  hydrooj addon add /root/.hydro/addons/OfficialSolution
  hydrooj addon add /root/.hydro/addons/HomePage
  hydrooj addon add /root/.hydro/addons/VipIntroPage
  hydrooj addon add /root/.hydro/addons/FishOjTheme
  hydrooj addon add /root/.hydro/addons/hydroac-client
  pm2 restart hydrooj
'"
```

AI 助教/分析还要 `DEEPSEEK_API_KEY`（见换机文档）。SSE 长连接把仓库 [`server-config/Caddyfile`](../server-config/Caddyfile) 的 30 分钟超时覆盖进 Hydro 的 Caddy 配置后 `caddy reload`。

迁旧机用户和题目：优先官方 `hydrooj backup` / `hydrooj restore`，或本仓库 `server-config/migrate/`。

## 7. 常见失败

| 现象 | 原因 |
|------|------|
| 脚本跑完网站打不开 | 安全组没放行 80 |
| 装在 Alibaba Cloud Linux 上失败 | 发行版不受支持，重装 Ubuntu/Debian |
| 有宝塔抢 80 | 与官方 Caddy 冲突 |
| Nix / 清华镜像 403 | 换 `nix_install_source` 或换网络 |
| 能打开但不能评测 | `hydro-sandbox` 未 online；或 Docker 没 `--privileged` |
| `hydrooj: command not found` | 没用 root，或没 `bash -lc` 加载 nix |
