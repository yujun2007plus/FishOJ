# FishOJ 项目定位与开发指南

> **本文档是 FishOJ 的「总纲」**：新增插件、改功能、用 AI 生成代码前，应先对照本文判断方向是否正确。  
> 描述的是 **当前真实状态 + 长期约束**，不是愿景清单。细节实现见各插件目录与 [`problem-ide-learning-contract.md`](problem-ide-learning-contract.md)。

---

## 1. 一句话定位

**FishOJ = 官方 Hydro OJ + 自研插件层**，面向 **少儿编程培训班** 的做题与教学体验，**不 fork、不改 Hydro 核心**。

本 Git 仓库 **只有插件、文档、配置样例**；Hydro 安装包、MongoDB 数据、题库大文件、支付密钥 **不在仓库内**。

---

## 2. 我们是谁、为谁做、解决什么问题

| 维度 | 说明 |
|------|------|
| **用户** | 校外少儿编程班：学员（小学生/初中生为主）、老师、后续可能的机构管理员 |
| **场景** | 日常刷题、课中练习、赛后复盘；不是 ICPC/NOI 竞赛级命题平台 |
| **核心价值** | 在标准 OJ 评测能力之上，提供 **LeetCode 式 IDE 做题体验** + **可控的 AI 辅助**（引导而非代写） |
| **作者目标** | 以真实项目学习服务器、前后端、插件架构；最终服务培训班落地 |

### 学员侧体验目标

- 编程题默认进入 **左右分栏 IDE**（`/ide/:pid`），而不是 Hydro 默认长文 + 底栏提交框
- 自测、提交、历史记录 **与官方评测一致**，不重复造轮子
- AI 能力 **可选、可关、失败不影响提交**；小助手偏启发，助教偏多轮讲解，分析偏错因复盘

### 老师/机构侧（部分已实现、部分规划中）

- 按题配置：是否启用脚手架、编程小助手、AI 助教（LearningScaffold + 控制面板）
- 会员/冷却等商业能力 **仅预留挂钩**（VipIntroPage），支付未接通
- 题目编辑、题包导入 **沿用 Hydro 官方**（`/p/:pid/edit`），FishOJ 暂未做 CodeFun 式扩展编辑页

## 3. 架构分层：什么在哪里

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器                                                      │
│  /ide/:pid  → ProblemIde 模板 + 各插件 *.page.ts 打包 UI    │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  FishOJ 自研插件（本仓库 addons/）                           │
│  ProblemIde · LearningScaffold · AiTutor · AiAssistant ·    │
│  AiAnalysis · VipIntroPage                                   │
└───────────────────────────┬─────────────────────────────────┘
                            │ Hydro 插件 API（Route / Hook / injectUI）
┌───────────────────────────▼─────────────────────────────────┐
│  Hydro 官方核心（服务器全局安装，不在本仓库）                 │
│  用户/域/权限 · 题目 CRUD · 提交/记录 · 比赛作业 · 沙箱评测   │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  基础设施：MongoDB · hydro-sandbox · Caddy · PM2             │
└─────────────────────────────────────────────────────────────┘
```

**铁律：**

1. **评测、权限、用户体系** → 用 Hydro 官方，不在插件里重写
2. **体验层、教学层、AI 层、商业展示层** → 做在自研插件里
3. **插件之间禁止 `import` 对方内部文件**；只通过 **公开协议** 协作（见第 6 节）

## 4. 产品支柱与插件归属

新增功能时，先问：**属于哪一根柱子？** 再决定 **新建插件** 还是 **扩展现有插件**。

| 支柱 | 含义 | 已有插件 | 边界 |
|------|------|----------|------|
| **A. 做题 IDE** | 题面 + Monaco + 自测/提交 + 控制台 | `ProblemIde` | 不做 AI 逻辑、不做会员判断、不做支付；只做 **宿主协议** 与 IDE 本体 |
| **B. 教学配置** | 按题开关脚手架/小助手等 | `LearningScaffold` | 管理后台与 `fish_learning_problem` 元数据；不直接调 LLM |
| **C. AI 辅助** | 三类能力，职责分离 | 见下表 | 均依赖 ProblemIde 事件/快照；互不 import |
| **D. 商业/运营** | 会员介绍、冷却挂钩 | `VipIntroPage` | 不做订单/微信支付；只暴露 `ideShortCooldown` 等字段供别人 hook |
| **E. 官方能力** | 改题、导题、比赛 | （Hydro 核心） | FishOJ **不搬** CodeFun 的 ProblemTag/ProblemPages 编辑页，除非单独立项 |

### C. AI 辅助：三个插件，不可混用

| 插件 | 用户可见名 | 技术特征 | 禁止做的事 |
|------|------------|----------|------------|
| `AiTutor` | 编程小助手 | 启发式 `/ai-tutor/hint`，短问句、分级 H1–H4 | 不要做成多轮聊天；不要替代助教 |
| `AiAssistant` | AI 助教 | SSE 多轮 `/ai-assistant/stream`，历史、引用代码 | 不要塞入提交分析；入口在 IDE 设置/浮层 |
| `AiAnalysis` | AI 分析 | 对 **提交记录 rid** 流式分析 `/ai-analysis/stream` | 不要绑在编辑区实时；必须 **先选记录再点开始** |

协作关系（宿主 = ProblemIde）：

```
ProblemIde
├── 右上角 ⚙ → AI 助教显示开关
├── AiAssistant（右）─灯泡→ AiTutor（左，嵌入时隐藏 🤖）
├── AiAnalysis（左 Tab「AI分析」）
└── learning.* 开关由 LearningScaffold / AiTutor hook 写入
```

## 5. 与 CodeFun2000.addons 的关系

[`codefun2000.addons分析.md`](codefun2000.addons分析.md) 记录的是 **商业 Hydro 插件样板**（60+ 插件）。

| 态度 | 说明 |
|------|------|
| **借鉴** | 产品形态（IDE 布局、AI 分析两步流、会员页结构）、文件拆分方式 |
| **不复制** | 支付密钥、订单表、反爬、题库章节 API、ProblemTag 扩展编辑整套 |
| **对照开发** | 遇疑问可先查 CodeFun 对应插件，再 **按 FishOJ 协议重写**，不要整包拷贝 |

常见对照：

| 需求 | CodeFun 参考 | FishOJ 现状 |
|------|--------------|-------------|
| 做题 IDE | `ProblemPages` + `problem_ide.page.ts` | `addons/ProblemIde`（已拆多文件） |
| AI 分析 | `AI-addon` + `ProblemPages` 内嵌 | 独立 `addons/AiAnalysis` + 事件协议 |
| AI 助教 | CodeNote / 笔记场景 | `addons/AiAssistant` + acm-problem 场景 |
| 编辑题目 | `ProblemPages/problem_edit.html` + `ProblemTag` | **未做**；用 Hydro `/p/:pid/edit` |
| 会员支付 | 多个商业插件 | 仅 `VipIntroPage` 介绍页 |

## 6. 跨插件协作协议（必须遵守）

公开契约文档：[`problem-ide-learning-contract.md`](problem-ide-learning-contract.md)

**合法方式：**

| 方式 | 示例 |
|------|------|
| `handler/after` 改 `response.body` | `AiAnalysis` 写 `body.aiAnalysis.enabled` |
| 模板写入 `UiContext` | `problem_ide.html` 默认字段 + hook 覆盖 |
| `document` CustomEvent | `problem-ide-submit-result`、`problem-ide-ai-analysis-open` |
| `window` CustomEvent | `cf-assistant-set-dismissed` |
| 约定 URL | `/vip`、`/ai-tutor/hint` |

**禁止：**

- 插件 A `import` 插件 B 的 `handler/`、`lib/`、`frontend/` 内部模块
- 在 `ProblemIde` 里写死 AI 提示词、会员支付、LLM 调用
- 判题/提交路径依赖 AI 返回才继续

ProblemIde 对外快照：

```js
window.FishOJProblemIde.getSnapshot()
window.FishOJProblemIde.hasMeaningfulCode()
```

## 7. 新功能决策清单

加功能或改代码前，按顺序过一遍：

### 7.1 该不该做？

- [ ] Hydro 官方是否已有？（用户、题目、提交、比赛、域权限）→ **有则用官方，不重做**
- [ ] 是否属于「评测核心」？→ **否才能做在插件**
- [ ] 是否与现有某插件职责重叠？→ **扩展原插件，避免第三个 AI 聊天**

### 7.2 放在哪个插件？

```
新功能是否只影响 /ide/:pid 页？
  ├─ 是，且是 IDE 布局/自测/题面 → ProblemIde
  ├─ 是，且是 AI → AiTutor / AiAssistant / AiAnalysis（按上表选）
  ├─ 是，且是教学元数据/开关 → LearningScaffold
  ├─ 是，且是会员/冷却 → VipIntroPage 或 hook ideShortCooldown
  └─ 否（全站、管理端、独立 URL）→ 新建 addons/<Name>/
```

**新建插件条件：** 独立路由、独立管理页、可单独启停、与现有插件无共用生命周期。

### 7.3 怎么协作？

- [ ] 是否只需改 `UiContext` / CustomEvent？→ 优先，不改 ProblemIde 源码
- [ ] 是否需要新 HTTP 路由？→ 放在 **功能所属插件** 的 `handler/`
- [ ] 是否影响 SSE/长连接？→ 同步 `server-config/Caddyfile` 超时配置

### 7.4 怎么交付？

- [ ] `hydrooj addon add` + `pm2 restart hydrooj`（改 `*.page.ts`/CSS 必须重启）
- [ ] 更新 [`problem-ide-learning-contract.md`](problem-ide-learning-contract.md)（若新增公开事件/字段）
- [ ] 区分 **「代码已合并」** 与 **「服务器已部署」**

## 8. 代码组织约定

每个插件推荐结构（与现有代码一致）：

```
addons/<FeatureName>/
  index.ts              # 仅 apply()：注册路由、钩子
  handler/              # HTTP Handler
  hooks/                # ctx.on('handler/after')
  lib/                  # 纯函数、无 Hydro 上下文也可测
  frontend/
    <feature>.page.ts   # NamedPage(['page_name']) 入口
    *.ts / *.css        # 按功能拆模块
  templates/            # Nunjucks
  package.json          # main: index.js
```

编写约定：

1. **`index.ts` / `*.page.ts` 只做组装**，不写大段业务
2. **中文 UI**；管理端可 i18n
3. **AI 生成代码** 同样遵守上述边界（见 README「插件开发约定」）
4. **密钥、Mongo URI** 不进 Git；用环境变量或 Hydro SystemSetting

## 10. 当前能力边界（避免规划过度）

### 已有（代码 + 多数已部署试用机）

- ProblemIde：`/ide/:pid`，自测/提交/历史/考试模式
- LearningScaffold、AiTutor、AiAssistant、AiAnalysis
- VipIntroPage：`/vip`（支付未接通）
- Caddy SSE 超时样例

### 明确未做（不要假设仓库里有）

- 微信支付、订单、拼团核销
- CodeFun 式 **扩展题目编辑**（ProblemTag、TextSol 字段编辑页）
- 题库章节 API（IDE 抽屉「章节/题库」后端未接）
- 班级/家长报告产品化（可用 Hydro 作业/比赛组合，但未定制）
- Docker 编排、CI 自动部署
- `DEPLOY.md` 独立文档（流程在 README）

### 非目标（当前阶段）

- Fork Hydro 或自研沙箱
- 把 CodeFun 60+ 插件整体迁入
- 在 ProblemIde 内嵌「编辑题目」

## 11. 路线图（与定位对齐）

| 阶段 | 内容 | 与定位关系 |
|------|------|------------|
| 一、上线 | 服务器 + Hydro + 公网 | ✅ 基础设施 |
| 二、深挖 | Docker、Mongo、Hydro 原理 | 支撑正确运维，不改变产品定位 |
| 三、插件 | IDE + 教学 + AI | ✅ **当前主战场** |
| 四、运营 | 备案、支付、监控、正式 Docker | 商业闭环，不反哺评测核心 |

阶段三的优先级建议：

1. 稳定 IDE + AI 链路（体验、额度、Key 配置）
2. 教学配置产品化（Scaffold/Tutor 按题启用流程）
3. 会员/支付 **仅在 VipIntroPage 插件内闭环**
4. 题库/章节 **独立 API 插件**，不塞进 ProblemIde
5. 题目编辑 **若要做**：单独立项参考 ProblemPages+ProblemTag，勿塞进 IDE
