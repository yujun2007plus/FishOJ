## 1. 一句话

FishOJ 是面向少儿编程培训班的 Online Judge：**官方 Hydro 核心不 fork**，业务全部做在 **addon 插件**里。本 Git 仓库主要是插件层、文档和配置样例，**不包含** Hydro 官方源码、MongoDB 数据和题库大文件。

## 3. 运行时拓扑（线上）

```
浏览器
  → :80 Caddy（gzip、静态 /root/.hydro/static、其余反代）
    → 127.0.0.1:8888  HydroOJ 主进程（PM2 名 hydrooj）
         → MongoDB 7.0（本机，PM2）
         → hydro-sandbox + Nix 编译器工具链（评测）
```

- 进程：`hydrooj` / `mongodb` / `hydro-sandbox` / `caddy`（均 PM2）。
- 插件安装目录（服务器）：`/root/.hydro/addons/<AddonName>/`，清单在 `/root/.hydro/addon.json`。
- UI 打包：改 `frontend/*.page.ts`、CSS 后需在 Hydro 侧 **重建前端** 并重启 `hydrooj`；只改 Nunjucks 模板有时刷新即可，生产常有缓存。
- 本仓库 `server-config/` 是配置**样例**（Caddyfile、`config.example.json` 的 Mongo URI 占位），**不要把真实密码提交进 Git**。

常用命令（服务器）：

```bash
pm2 list
pm2 restart hydrooj
pm2 logs
hydrooj cli user setSuperAdmin <uid>
hydrooj addon add <path>    # 安装插件后需写进 addon.json 并重建 UI
```

## 5. Hydro 二次开发机制（脚手架必须遵守）

Hydro 插件是一个带 `package.json`（`main` 指向编译后的 `index.js`）的目录，导出：

```ts
export function apply(ctx: Context) { /* 注册路由、钩子、UI、i18n */ }
```

典型能力：

| API | 用途 |
|---|---|
| `ctx.Route(name, path, Handler, perm?)` | HTTP 路由 |
| `class X extends Handler` | 服务端页面/接口，`response.template` + `response.body` |
| `ctx.on('handler/after/...')` / `ctx.on('handler/after')` | 不改对方插件，只改响应 |
| `ctx.withHandlerClass('ProblemSubmitHandler', ...)` | 继承官方 Handler |
| `ctx.injectUI('Nav', ...)` | 顶栏导航 |
| `ctx.i18n.load` | 文案 |
| `ctx.setting.SystemSetting` | 系统设置项 |
| `DomainModel.addRole` | 域角色 |
| `frontend/*.page.ts` + `addPage(new NamedPage(['page_name'], ...))` | 仅该页打包进 UI |
| `templates/*.html`（Nunjucks，`{% extends "layout/basic.html" %}`） | 服务端渲染 |

**`page_name` 必须与模板 / NamedPage 一致**（做题页 `problem_ide`，会员页 `vip`）。

前端约定：

- 页面脚本：`addons/<Name>/frontend/<name>.page.ts`（Hydro webpack 按 `*.page.ts` 收集）。
- 样式：同目录 CSS，由 page 入口 `import`。
- 模板把数据塞进 `UiContext` 或 `window.__xxx`，page 脚本读取。
- 提交/自测走 **官方已有接口**（如 `problem_submit`、`record-conn` WebSocket），插件不要重复实现评测核心。

### 插件目录脚手架（推荐，与现有两插件对齐）

```
addons/<FeatureName>/
  package.json              name: fishoj-xxx, main: index.js
  index.ts                  只 apply()：组装，不写业务细节
  types.ts                  仅当需要扩展 hydrooj 模块类型时
  handler/<feature>.ts      路由与 Handler
  hooks/<event>.ts          ctx.on / 与其它页约定字段
  lib/*.ts                  纯函数、角色、配置键
  frontend/
    <feature>.page.ts       NamedPage 胶水
    *.ts                    按功能拆的模块
    <feature>.css
  templates/
    <feature>.html
    partials/*.html
```

禁止：改 Hydro 核心；插件 A `import` 插件 B 的内部文件；把会员判断写进做题插件。

跨插件协作的**合法**方式（已有实例）：

- 页面 A 在 `response.body` 放一个**默认字段**（如 `ideShortCooldown = false`）。
- 页面 B 在 `handler/after` 里若 `template === 'problem_ide.html'` 则改写该字段。
- 或只链到对方 **URL**（做题页 toast 链到 `/vip`），不 import。

## 7. 插件：ProblemIde（做题 IDE）

**目标**：编程题默认进入左右分栏 IDE，而不是 Hydro 默认「长文 + 底下提交框」。视觉见 `docs/problem-ide-风格.md`（Ant Design 4 + LeetCode 式：左题面、右 Monaco、底栏用例/结果/历史）。

| 项 | 值 |
|---|---|
| 路由名 | `problem_ide` |
| URL | `/ide/:pid` |
| 权限 | `PERM.PERM_VIEW_PROBLEM` |
| 模板 | `problem_ide.html` |
| 前端页 | `problem_ide.page.ts`（另：`problem_list_same_tab.page.ts` 拦截题单链接） |

行为要点：

- `/p/:pid` 在 `ProblemDetail#get` 之后 **302 到** `/ide/:pid`（保留 query）。**客观选择题**（`pdoc.config.type === 'objective'`）不跳转，仍用官方详情。
- IDE 的 POST 故意拒绝，真正提交走 `postSubmitUrl`（官方 `problem_submit`）；自测 `pretest: true`，结果走 `record-conn` WebSocket。
- 未登录：不能自测/提交，可弹登录框。
- 选择题以外的编程题：语言列表来自题目 `config.langs` 或全站语言。
- `ideShortCooldown` **本插件只设 `false`**；VIP 插件可覆盖。模板写入 `UiContext.ideShortCooldown`。
- 题库抽屉 / 章节切换请求 `/api/problem/ide-pset-list`、`/api/problem/ide-pset-section`——**后端尚未实现**，前端失败时展示「未接入」文案。
- 样例：把 Hydro 的左右 `.row` 展平为上下对齐的「输入数据 N / 输出数据 N」，支持复制、填充到自测（事件 `problem-ide-fill-pretest-case`）。
- 练习/考试模式、计时器、题面目录 TOC、算法标签展开：纯前端。

文件职责（生成新文件时按此粒度拆）：

- 后端：`handler/problemIde.ts`、`hooks/redirectDetail.ts`、`lib/objective.ts`、`lib/langRange.ts`
- 题面：`samples.ts`、`statementHeading.ts`、`statementToc.ts`、`algTags.ts`、`timer.ts`、`expMode.ts`
- 题库 UI：`psetNav.ts`、`psetDrawer.ts`、`sectionSwitcher.ts`
- 编辑器：`monaco.ts`、`editor.ts`、`splitLayout.ts`、`tabs.ts`、`drawer.ts`、`cases.ts`、`codeTemplate.ts`、`http.ts`、`constants.ts`
- 评测会话：`judge/session.ts`
- `index.ts` / `*.page.ts` 只组装

## 8. 插件：VipIntroPage（会员介绍）

**目标**：独立会员落地页；会员身份用 **域角色 `vip`**（权限拷贝自 `default`），不是另做一套用户表。

| 项 | 值 |
|---|---|
| 路由名 | `vip` |
| URL | `/vip` |
| 导航 | `ctx.injectUI('Nav', 'vip', { before: 'training_main' })`，中文「会员」 |
| 模板 | `vip.html` + partials |
| 前端 | `vip_intro.page.ts` |

已实现：

- 状态：`guest` / `non-vip` / `vip`（`user.role === 'vip'` 或 `roles` 含 vip；uid≤1 不当会员）。
- 启动时 `ensureVipRole()`：每个域若无 `vip` 角色则 `DomainModel.addRole`；新域 `domain/create` 时写入。
- 系统设置键 `fishoj.vip_notice`（Markdown 公告）。
- 套餐展示（标价 ¥256 / 拼团 ¥199）、FAQ、拼团说明弹窗。
- `handler/after`：若当前是做题页，则 `body.ideShortCooldown = isVipUser(user)`。

明确 **未实现**（计划书应单列，不要假装已有）：

- `vipCheckoutReady` 恒为 `false`；结账按钮走「支付即将开放」。
- 无 `/buy/vip`、无微信支付、无拼团订单/核销、无会员到期时间字段。
- 管理员目前需在域用户管理里把角色改成 `vip`。

**禁止**把 `isVipUser` 拷进 ProblemIde。

## 10. 给「功能代码脚手架」的硬约束

生成任意新功能时：

1. **新功能 = 新 addon 目录**（或明确属于现有插件的一个子模块）。不要往 `ProblemIde` 里塞会员/支付，不要往 `VipIntroPage` 里塞 Monaco。
2. `index.ts` 不超过「注册 + 调用 bindXxx」。
3. 每个文件一个职责；前端 `*.page.ts` 只引模块、绑 DOM。
4. 能用官方 Model/Handler/路由就用；新 API 路径放在本插件 `handler/`。
5. 与其它插件交互：hook + 约定字段 / URL / 事件名，禁止跨包 import。
6. 模板继承 `layout/basic.html`；需要整页 IDE 再学 ProblemIde 的 `position:fixed` 覆盖页脚。
7. 中文 UI；管理端文案可中英 i18n。
8. 不提交密钥、不把真实 Mongo URI 写入仓库。
9. 改 UI 后说明：需 `hydrooj addon` + 重建前端 + `pm2 restart hydrooj`。
10. 未部署到服务器的插件，计划里标「代码 / 部署」两列。
